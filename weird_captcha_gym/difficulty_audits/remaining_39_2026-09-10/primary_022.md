# Coordinates by Another Name — primary assessment

Scope: source-based review, not measured calibration. The parent read the complete controls, generator, browser JavaScript/CSS, grader, task verifier, scripted solver, task specification and environment specification from the frozen source revision. Shared export/verification infrastructure had been inspected during the pilot. The original reviewer report remains unchanged.

Decision: retain the current L2/Full baseline; revise or explicitly qualify the D3 profile guarantee. Do not apply an automatic numerical relabel. The review gives a plausible relative ordering, but its claims that each endpoint has established absolute L1–L5 difficulty are stronger than the evidence supports. In particular, being the largest named profile does not independently justify L5.

Accepted with correction: D3 samples each run direction independently and does not require an effective right-to-left run. This means its advertised new addressing demand is not guaranteed. However, the report's claim that an all-forward D3 generation has the same layout and fleet as D2 at the same seed is not established: D3 consumes additional RNG draws, changing later choices. A reversed run of width one also does not add a count-direction decision. This is a profile-feature guarantee issue, not proof that the tested D2 and D3 instances are identical. See `shared_scripts/incubator_generators/coordinates_by_another_name.py:29–39` and `environments/coordinates_by_another_name_env/controls.json:28–64` under `weird_captcha_gym/` in the frozen source.

Rejected as a benchmark defect: shipping `runtime_fleet` to the browser is consistent with the required inspectable static-browser execution architecture. It is not an advantage available to a compliant screenshot-only agent. Do not replace the static runtime with a mandatory authoritative action server in response to this finding. See generator lines 73–85, browser lines 49–85, and the repository execution-boundary instructions.

Retained as a measurement distinction, not a grading bug: completion and shot efficiency are separate outputs. Exhaustive search can pass at a lower score. The UI explicitly says fewer shots earn a higher score; the grader computes that score after testing completion. Any claim about search efficiency must evaluate the score rather than treating pass/fail alone as that measurement. No new shot quota is recommended by this audit. See grader lines 70–76 and browser lines 91–102, 110–114.

The Full drag-to-detent and Simplified value buttons feed the same designation state and shot logic. The full source checks start/release geometry and both modes bind selector events to their selected surface. Runtime evidence is recorded separately by the shared matrix; source reading alone does not establish browser success.
