# Lantern Loft — primary assessment

Decision: revise the interaction comparison and profile descriptions; retain the existing L4/Full label provisionally, without claiming calibrated absolute L1–L5 assignments. The parent read the complete controls, generator, browser JavaScript/CSS, grader, task verifier, scripted solver and task/environment specifications. Original reviewer findings are preserved separately.

The information mismatch is supported. Simplified lists `legalSteps()` and `legalSlides()` as buttons after each update, whereas Full supplies only a direct-manipulation hint. In particular, the walking list computes the opening/elevation/stair predicate for the player. The underlying world and effects are shared, but the input modes do not provide the same assistance with deciding what is connected. See browser lines 50–59, 71–91 and 171–185. This is not a claim that all proxy buttons are inherently unfair: these buttons reveal the result of the task-relevant connectivity test.

The D5 decoy-opening parameter is inactive: eight route modules leave zero decoy modules. Elevation changes are also not generated as exact counts; the height saturates at two, and some unselected positions step down. All three tested D4 worlds have two route-height transitions despite a configured three. D5 seeds 1, 17 and 101 have respectively two, two and four transitions despite a configured five. See generator lines 166–171, 179–182 and 212–220, and `lantern_loft_structure_checks.json`.

The distinction between scramble length and required solving actions matters in actual generated examples. Exact breadth-first search under the existing transition predicates found an exit route with zero slides for all three D1 seeds and D3 seed 1. D5 seed 101 has an eight-action solution, while its D4 counterpart needs ten actions. These are structural diagnostics, not evidence that a screenshot-only player would find those paths or that fewer actions alone means easier. They do refute treating the stored scramble witness as a mandatory solution length. No action quota is recommended; if reconfiguration is intended to be required, the generated initial connectivity must establish that requirement.

Additional parent source and rendered observation: the board-shadow loop calls `slot(x + y * 3)` even though `slot` takes `(x, y)`. That produces non-finite slot coordinates. The captured D4/Full initial render shows separated module platforms without the intended empty-position/background polygons. The Full hit test still uses finite empty-slot polygons and the HUD exposes the open-rail number, so this is a missing visual target cue, not evidence of unsolvability. The player may still infer an empty location from the regular layout. See browser lines 15–16, 24–30, 40–47 and 129–136, and `screenshots/035_lantern_loft_d4_full_seed1_solve/initial.png`.

All file references above are under `weird_captcha_gym/` in the frozen source, chiefly `shared_runtime/app/mechanics/lantern_loft.js` and `shared_scripts/incubator_generators/lantern_loft.py`. Numerical baselines and puzzle sources have not been changed.
